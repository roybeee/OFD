# OFD 프랜차이즈 워크스테이션 — 서버판 v1

가맹 영업 파이프라인(숙려기간 게이트) · 발주 · 매출 마감(POS CSV) · 정산 · 공지 · 매장 대장 · 감사 로그.
**의존성 0개** — Node.js 내장 모듈만 사용합니다(`node:http`, `node:sqlite`, `node:crypto`). `npm install`이 필요 없습니다.

## 계정 체계 (부서별 권한 분리)

| 기능 | 마스터 | 관리 | 운영 | 영업 | 점주 |
|---|:-:|:-:|:-:|:-:|:-:|
| 가맹 영업 파이프라인 (숙려 게이트 포함) | O | - | - | O | - |
| 발주 상태 전이·반려 | O | - | O | - | - |
| 매출 마감 입력·POS CSV | O | - | O | - | 자기 매장 |
| 매장 등록·삭제 / 접속코드 발급 | O | - | O | - | - |
| 공지 게시 | O | - | O | - | 열람 |
| 정산 조회 | O | O | - | - | - |
| SKU·가격 관리 | O | O | - | - | - |
| 감사 로그 열람 | O | O | - | - | - |
| 계정 관리 / 백업·이관 | O | - | - | - | - |

- 초기 설정에서 **마스터 계정**(아이디·비밀번호)을 만들고, 부서 계정은 설정 → 계정 관리에서 추가합니다.
- 모든 권한은 **서버가 강제**합니다(부족 시 403 + 필요 권한 반환). 감사 로그는 "이름 (부서)" 개인 단위로 남습니다.
- 마지막 활성 마스터는 강등·비활성·삭제할 수 없습니다. 계정 비활성·비밀번호 재설정 시 해당 세션은 즉시 무효화됩니다.
- **v1(단일 PIN) DB 자동 이관**: 기존 서버 DB로 기동하면 `master` 아이디 / 비밀번호 = 기존 PIN 계정이 자동 생성됩니다. 최초 로그인 후 비밀번호를 변경하십시오.

## 서버가 강제하는 것 (아티팩트 파일럿판과의 차이)

| 항목 | 아티팩트판 (파일럿) | 서버판 (본 패키지) |
|---|---|---|
| 인증 | 클라이언트 검증 (우회 가능) | 서버 세션 (HttpOnly 쿠키, scrypt 해시) |
| 권한 | 화면 분리 수준 | 모든 API에서 역할 검증 — 점주는 자기 매장 데이터만 |
| 숙려기간 (가맹사업법 제7조③) | 화면 경고 | **서버가 거부** (409) — 사후기록은 override 명시 + 플래그 + 감사 로그 |
| 발주 상태 전이 | 화면 버튼 | 본사 권한만, 정해진 순서만 허용 |
| 접속코드 | 평문 저장 | scrypt 해시만 저장, 발급 시 1회 노출, 재발급 시 기존 세션 즉시 무효화 |
| 감사 로그 | 클라이언트 기록 | 서버 타임스탬프 기록 (위조 불가) |
| 무차별 대입 | 없음 | 인증 시도 분당 제한 (429) |

## 요구사항

- Node.js **22.5 이상** (`node:sqlite` 내장 버전)
- 그 외 없음

## 로컬 실행

```bash
node --no-warnings server.js
# → http://localhost:8787
```

첫 접속 시 초기 설정 화면에서 관리자 PIN을 만들면 DB(`ofd.db`)가 생성되고,
예시 매장들의 점주 접속코드가 **1회** 표시됩니다. 반드시 기록하십시오.

## 환경변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | 8787 | 수신 포트 |
| `DB_PATH` | ./ofd.db | SQLite 파일 경로 |
| `SECURE_COOKIES` | (off) | `1`이면 쿠키에 Secure 플래그 — **HTTPS 운영 시 필수** |
| `SESSION_HOURS` | 12 | 세션 유효시간 |

## 운영 배포

**HTTPS는 필수입니다.** 접속코드·PIN이 평문으로 전송되므로 반드시 TLS 뒤에 두십시오.
가장 간단한 방법은 Caddy 리버스 프록시입니다(인증서 자동 발급):

```
# /etc/caddy/Caddyfile
ops.example.co.kr {
    reverse_proxy 127.0.0.1:8787
}
```

서버 측은 `SECURE_COOKIES=1`로 기동합니다.

### 방법 A — systemd (권장)

```bash
sudo mkdir -p /srv/ofd-workstation-server && sudo cp -r . /srv/ofd-workstation-server
sudo useradd -r ofd && sudo chown -R ofd /srv/ofd-workstation-server
sudo cp ofd.service /etc/systemd/system/ && sudo systemctl enable --now ofd
```

### 방법 B — Docker

```bash
docker build -t ofd-workstation .
docker run -d --name ofd -p 127.0.0.1:8787:8787 -v /srv/ofd-data:/data ofd-workstation
```

## 토스플레이스 POS 연동 (매장별 매출 자동 수집·분석)

**동작 방식**
- 토스플레이스 Open API에서 **완료(COMPLETED) 주문만** 가져와 KST 기준 시간대×품목으로 적재합니다.
- 30분마다 오늘·어제를 자동 재수집하며, 같은 날짜는 **전량 재계산**되므로 취소 건이 자동 반영됩니다(멱등).
- 수집된 판매수량은 매출 마감에 자동 반영되고, 점주가 입력한 **폐기수량은 보존**됩니다.
- POS 품목명이 SKU와 다르면 "미매칭"으로 분리되어 설정 → POS 연동에서 **별칭 매핑** 시 과거분까지 소급 재계산됩니다.
- API 키는 AES-256-GCM으로 암호화 저장되며 화면·백업 어디에도 노출되지 않습니다. (운영 환경에서는 `OFD_SECRET` 환경변수로 암호화 키를 지정하십시오)

**연동 절차 (매장별)**
1. 해당 매장의 토스플레이스 계정으로 [개발자센터](https://developers.tossplace.com/) 가입 → 앱 생성 → `x-access-key` / `x-secret-key` 발급
2. 매장 ID(merchantId) 확인
3. 워크스테이션 설정 → POS 연동(운영/마스터 권한)에서 매장별로 입력 → 저장 → [동기화]로 즉시 검증
4. 키 발급 전에는 제공자 `mock`으로 전체 파이프라인(수집→마감→분석)을 시연·검증할 수 있습니다.

**분석 탭** — 관리·마스터(전 매장) 및 점주(자기 매장): 일별 추이(주말 강조), 시간대별 매출(08~22시), 상품 믹스 비중, 주중/주말 일평균, 직전 동일 기간 대비 성장률. POS 미연동 매장은 마감×정가 기준으로 폴백 표시됩니다.

## 백업

데이터는 SQLite 파일 하나입니다. 야간 크론 예시:

```bash
# crontab -e
30 3 * * * sqlite3 /srv/ofd-workstation-server/data/ofd.db ".backup /srv/backup/ofd-$(date +\%F).db"
```

추가로 본사 설정 탭의 **JSON 내보내기**는 사람이 읽을 수 있는 논리 백업입니다(코드·PIN 해시는 포함되지 않음).

## 아티팩트(파일럿)판에서 이관하기

1. 아티팩트판 설정 탭 → **JSON 내보내기**로 백업 파일 저장
2. 서버판 본사 설정 탭 → **JSON 가져오기(병합)** — 수정시각 최신 우선으로 병합됩니다
3. 이관된 매장은 접속코드 **미발급**, 이관된 계정은 비밀번호 **미설정** 상태입니다(보안상 해시는 이관하지 않음). 설정 탭에서 각각 재발급·재설정 후 전달

## 남은 정직한 한계

- 2단계 인증(OTP)은 아직 없습니다. 마스터·관리 계정은 강한 비밀번호를 사용하십시오.
- 단일 서버 구성입니다. 이 규모(수십 매장, 저빈도 트랜잭션)에는 충분하지만 무중단 이중화는 없습니다.
- 로열티 정산 모듈은 제4조 자료(기존 가맹계약서·산정기준) 수령 후 요율을 확정해 추가합니다.
- POS 연동은 30분 폴링 방식입니다. 실시간성이 필요해지면 토스플레이스 웹훅 수신 엔드포인트를 추가하면 됩니다.
- 실계정 스모크 테스트는 매장별 API 키 수령 후 1회 필요합니다(mock 파이프라인은 전 구간 검증 완료).
