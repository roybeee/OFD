## 1. 반영한 기능

### 1.1 인증 — MFA 제거와 비밀번호 정책

| 항목 | 이전 | 현재 |
|---|---|---|
| 로그인 | 본사·감사 계정은 비밀번호 + TOTP 6자리 | **비밀번호만** |
| 중요 작업 본인 확인(스텝업) | 비밀번호 + TOTP | **비밀번호만** |
| 비밀번호 규칙 | 12자 이상 + 대문자·소문자·숫자·특수문자 | **10자 이상 + 숫자·특수문자** |
| 저장된 TOTP 비밀키 | 존재 | 마이그레이션 010으로 **일괄 제거** |

- 정산·세금계산서 승인 등 중요 작업의 **스텝업 요구 자체는 유지**된다(5분 이내 비밀번호 재확인).
  MFA만 없앤 것이지 이중 확인 절차를 없앤 것이 아니다.
- **최초 로그인 시 비밀번호 변경 강제**: 관리자가 계정을 만들거나 비밀번호를 재설정하면
  `mustChangePassword` 플래그가 서고, 본인이 바꾸기 전까지 **서버가 모든 업무 API를 403으로 차단**한다
  (`PASSWORD_CHANGE_REQUIRED`). 비밀번호 변경과 로그아웃만 허용해 잠금에서 빠져나올 수 있다.
  화면만 막으면 주소 직접 입력으로 우회되므로 서버에서 강제하는 것이 핵심.
- 계정 관리에 **내 비밀번호 변경** 추가. 변경 시 다른 기기 세션은 종료되고 현재 창은 유지된다.

### 1.2 계정 관리 — 권한·유형

- **계정 유형별 노출 페이지**: 역할(점주/매장직원/기사/본사운영/재무/최고관리자/감사자)마다
  보이는 메뉴를 체크박스로 지정. "기본값으로" 되돌리기 가능.
- **계정별 노출 페이지**: 등록 계정을 클릭하면 상세 설정이 열리고, 그 계정만의 노출 페이지를
  개별 지정할 수 있다. **계정별 설정이 역할 설정보다 우선**한다.
- **계정 유형 변경**: 상세 설정에서 역할을 바꾼다. 매장 역할로 바꾸면 배정 매장이 필수.
  안전장치 — 본인 계정 변경 불가, 마지막 활성 최고관리자 강등 불가, 배송 중 배정이 있는 기사 변경 불가.
- 설계 원칙: 페이지는 **같은 영역(store/hq/driver) 안에서만** 켜고 끌 수 있다. 승인·발행처럼
  역할이 고정된 액션은 페이지를 켜줘도 원래 역할이 없으면 서버가 거부한다(권한 상승 방지).

### 1.3 POS·매출

- **merchantId 자동 수집**: 매장 POS에 OFD 앱이 설치되면 토스가 보내는
  `app.installation.created.v1` 웹훅에서 merchantId를 받아 매출현황 연동 화면에 칩으로 노출.
  클릭하면 입력칸에 채워지고, 연동 등록이 끝나면 목록에서 사라진다.
  공식 규약대로 HMAC-SHA256 서명 검증 + `x-toss-webhook-id` 멱등 처리.
- **매출현황**: 매장 이름 표기(상점번호 아님), 품목 드릴다운에 **단가** 열 추가,
  **매출 숫자 클릭**으로도 드릴다운(매장 셀은 그 매장만, "전체 보기"로 복귀),
  품목 표 위 **카테고리별 매출 분포** 바·범례, **엑셀(CSV) 내보내기**(추출 항목 체크 선택).
- **상품 관리**: V1 백업 기반 **품목 41종 일괄 등록**, 카테고리·범위·소비자가 **인라인 수정**,
  **상품 클릭 시 매장별 현재 판매가**(기간 내 매출÷수량)와 등록가 대비 차이(%) 표시.

### 1.4 매장 대장 — 출점 거리 검토

가맹 상담 시 예비 출점지와 기존 매장 거리를 즉시 확인하는 용도.

- 기존 매장 = **파란 핀**, 예비 출점 후보 = **빨간 핀**(주소 입력으로 추가, 대장에 저장 안 하는 임시 표시)
- 후보 추가 즉시 **가장 가까운 기존 매장**과의 직선거리를 자동 표시
- 선택된 핀은 확대·흰 테두리로 강조, 후보 목록도 선택 시 강조

### 1.5 모바일·앱 설치(PWA)

- 모바일 내비게이션이 **글자 단위로 세로로 쪼개지던 문제** 수정 → 가로 스크롤 스트립
- 헤더 높이 **~230px → 135px** (브랜드+홈+로그아웃 한 줄)
- 표는 셀을 쪼개지 않고 가로 스크롤 + 첫 열 고정
- iPhone 안전영역(노치·홈 인디케이터) 대응
- **iOS 홈 화면 앱 지원**: iOS는 SVG 아이콘을 지원하지 않아 홈 화면 아이콘이 깨져 있었다 →
  PNG 아이콘 생성(180 iOS / 192·512 일반 / maskable 2종)
- **설치 안내**: 안드로이드는 브라우저 설치 프롬프트를 버튼으로 연결, **iOS는 프롬프트 API가
  없으므로**(애플 정책) "공유 → 홈 화면에 추가" 절차를 안내. 로그인 화면부터 노출.

## 2. 고친 결함 (원인 → 조치)

우선순위 순. 굵은 항목은 **프로덕션 장애**였다.

1. **매장 등록 500** — postgres CHECK 제약 `aggregate_store_scope_required`가 `store` 스냅샷에
   store_id를 요구하는데 3곳(매장 등록·대장 수정·가맹 오픈완료 자동 등록)이 스코프 없이 commit.
   메모리 저장소가 이 제약을 흉내내지 않아 테스트를 통과하며 새어나갔다.
   → 3곳 수정 + **MemoryRepository에 동일 제약 이식**(이식 직후 기존 테스트가 RED로 재현).
2. **502 전면 장애** — Render `preDeployCommand`는 셸이 아니라 `A && B`에서 B가 실행되지 않는다.
   그 결과 **DB 마이그레이션이 배포에서 한 번도 실행된 적이 없었고**(008도 수동 적용이었다),
   신규 마이그레이션 009가 포함되자 코드(9개 기대)와 DB(8개)가 어긋나 readiness 실패 →
   웹 헬스체크 연쇄 실패 → 502.
   → `predeploy-migrate.mjs` 단일 스크립트로 교체 + preflight에 자기 치유 로직
   (대시보드에 옛 명령이 남아 있어도 끊긴 체인을 이어서 실행) + 매니페스트 테스트에 `&&` 금지 가드.
3. **POS 동기화 404** — V1→V2 이식 시 토스 주문 조회 경로가 실제 API와 달랐다
   (`/orders?startDateTime=` ← 존재하지 않음). → V1과 동일한
   `/order/orders?from=&to=&orderStates=COMPLETED&sortOrder=ASC`로 복원 + 경로 고정 회귀 테스트.
4. **웹훅 저장 500(잠복)** — `recordWebhookInbox`가 실존하지 않는 컬럼(id, dedupe_key)에 INSERT.
   실제 webhook_inbox는 `(provider, event_id)` PK. 웹훅이 올 때마다 500이 났을 코드.
5. **네이버 지도 미표시(3단계)** — 우리 nginx CSP가 차단. ① 스크립트 도메인 → ② 타일 호스트
   `*.map.naver.net` → ③ 스타일 정의 JSONP(`nrbe.pstatic.net`, script-src). SDK 소스를 직접 분석해
   실참조 호스트를 확정하고, 프로덕션과 동일 CSP 재현 환경에서 렌더까지 확인.
6. **정산 KST 영업일 누락** — 확정 시각을 UTC로 잘라 00~09시(KST) 확정 입고가 전날로 밀려
   정산에서 빠졌다. → `operationalDateKst` 변환.
7. **루트 package.json 삭제** — 직전 커밋이 지워 npm workspaces·Docker 빌드가 불가능한 상태였다. 복원.
8. **CI 3중 실패** — 마이그레이션 목록 고정 테스트 / 모바일 가독성 게이트(제목 ≥30px) /
   설정된 적 없는 `RENDER_API_KEY`를 요구하던 배포 잡. 각각 수정·스킵 처리.
9. UI 회귀들 — 계정 목록 4열 grid 붕괴, 패널 여백, 헤더 내비 겹침, 정산 페이지 기본 노출 판정.

## 3. 다음 사람이 알아야 할 함정

### 3.1 배포(Render)

- **서비스가 render.yaml(blueprint)과 연결돼 있지 않다.** 대시보드 설정이 진실이며 render.yaml
  변경은 자동 반영되지 않는다. 배포 설정을 바꾸려면 대시보드(또는 Render MCP)에서 직접.
- `preDeployCommand`에 **셸 연산자(`&&`) 금지** — 뒤 명령이 조용히 무시된다.
  현재는 `predeploy-migrate.mjs` 단일 스크립트 + preflight 자기 치유로 이중 방어.
- 웹 서비스 healthCheckPath `/readyz`는 API로 프록시된다. **API readiness가 실패하면 웹 전체가 502**.
  스키마 마이그레이션이 포함된 배포는 반드시 `/readyz`의 `migrations.applied` 수를 확인할 것.
- 웹과 API는 **따로 배포**된다. 한쪽만 먼저 라이브일 수 있으니 양쪽 커밋을 각각 확인.

### 3.2 마이그레이션

새 마이그레이션을 추가하면 **목록을 고정한 테스트 2곳**을 함께 갱신해야 CI가 통과한다.
- `packages/db/src/migration-runner.test.ts`
- `packages/db/src/postgres.integration.test.ts` (CI 전용 — 로컬은 DATABASE_URL 없으면 skip되어
  로컬 검증만으로는 놓친다)

### 3.3 e2e·품질 게이트

- e2e에 **모바일 가독성 게이트**가 있다(390px에서 페이지 제목 ≥30px, 지표 라벨 ≥14px 등).
  타이포를 줄이면 여기서 걸린다.
- 본사 계정(ops·finance·master)은 로그인 후 **비밀번호 스텝업**을 해야 정산 초안 등이 통과한다
  (MFA 제거 전에는 MFA 로그인이 스텝업을 세워줬다). `e2e/real-fixture.ts`의 login 헬퍼가 처리한다.
- 로컬 e2e 실행:
  ```bash
  docker compose -f infra/docker-compose.yml up -d postgres
  # ofd_v2_e2e 데이터베이스 생성 후
  export DATABASE_URL='postgresql://ofd:ofd-local-only@localhost:5432/ofd_v2_e2e' \
         E2E_ALLOW_RESET=1 E2E_ALLOW_WRITES=1 E2E_SKIP_PREPARE=1
  npm run build:packages && npm run migrate -w @ofd/db && node e2e/seed-postgres.mjs && npm run e2e
  ```

### 3.4 데이터 시각화

카테고리별 매출 분포의 색은 **카테고리 이름에 고정 배정**돼 있다(도넛=파랑, 링도넛=주황…).
매출 순위로 배정하면 기간·필터가 바뀔 때마다 같은 카테고리 색이 달라져 읽을 수 없게 된다.
색맹 대비 검증(인접쌍 ΔE)을 통과한 8슬롯 팔레트를 쓰며, 값은 범례에 숫자로도 병기한다.

## 4. 남은 설정·후속 과제

### 지금 하면 좋은 것

| 항목 | 내용 |
|---|---|
| 토스 웹훅 서명 | 개발자센터에서 웹훅 등록(`https://ofd-web.onrender.com/api/v2/webhooks/tossplace`) 후 서명 Secret을 Render `ofd-api`의 `TOSSPLACE_WEBHOOK_SECRET`에 등록. **미설정이면 production에서 자동 수집이 보류**된다(위조 방지) |
| Pre-Deploy 명령 정리 | ofd-api Settings의 Pre-Deploy Command를 `node infra/scripts/deploy/predeploy-migrate.mjs`로 교체(현재는 자기 치유로 동작 중) |
| 상품 매칭 | 상품 관리 "미매칭 품목 정리"에서 POS 품목명↔상품 연결. 과거 매출까지 소급 반영되어 카테고리 분포·매장별 판매가가 정확해진다 |
| 기존 계정 비밀번호 | 강제 변경은 이번 배포 **이후** 생성·재설정된 계정에만 적용된다. 기존 계정에 적용하려면 계정 관리에서 비밀번호 재설정을 한 번 실행 |

### 검토 여지

- 모바일 상단 가로 스크롤 메뉴 → 자주 쓰는 화면이 정해져 있다면 하단 고정 탭바가 더 편할 수 있음
- CI 주도 배포를 쓰려면 GitHub Secret `RENDER_API_KEY` 등록(현재는 없으면 스킵, 서비스 ID 변수는 교정 완료)
