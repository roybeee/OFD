# ODA 매장 일일 업무

ODA 운영 대상은 `agent/oda-workstation-release` 브랜치와 기존 `oda-api` / `oda-web` 서비스다. 기존 인사관리의 근무표, 위치 확인 출퇴근, 근태 정정, 급여·정산 연결을 그대로 이용한다.

## 추가 범위

- 관리자와 연결된 직원이 날짜별 오픈·마감 체크리스트를 확인하고 완료 상태를 기록한다.
- 같은 매장의 인수인계 메모와 사진을 기록·조회한다.
- 초기 버전은 오픈 3개·마감 3개의 공통 점검 항목을 제공한다. 항목 사용자 정의는 이번 범위에 포함하지 않는다.
- 기존 HR 권한과 매장 범위, 버전 충돌 방지, 재요청 중복 방지, 감사 이력을 적용한다.
- 사진 원본은 ODA 전용 PostgreSQL의 별도 바이너리 테이블에 저장하며 HR 응답에는 메타데이터만 제공한다. 다운로드도 현재 로그인 권한과 매장 범위를 확인한다.
- 기존 직원 급여와 비공개 인사정보의 조회 제한은 유지한다.

## 배포 및 검증

- 기존 ODA DB `oda_production` / 역할 `oda_app` 연결을 이용한다. OFD의 DB·서비스 설정을 변경하지 않는다.
- 새 테이블은 추가형 마이그레이션으로 적용한다. 운영 데이터를 초기화하거나 합성 업무 기록을 생성하지 않는다.
- 단위·API·UI 테스트, PostgreSQL 호환 엔진 재시작 후 영속성 검증, 전체 CI 및 ODA 빌드를 수행한다.
- API를 먼저 배포하여 DB 마이그레이션과 readiness를 확인한 후 웹을 배포한다.

## 사용 방법과 제한

인사관리 → 매장 업무에서 날짜별 점검과 인수인계를 확인한다. 직원 홈과 더 보기에서도 진입할 수 있다. 직원은 재직 상태의 구성원 정보에 로그인 계정이 연결되어 있어야 한다. 사진은 JPEG·PNG·WebP 1장, 최대 2MiB이며 매장 구성원에게 공유된다. 관리자는 인수인계 해결·재오픈을 처리한다.

`014_oda_hr_photos` 마이그레이션은 원본 사진을 보존하는 추가형 변경이다. 되돌릴 때 테이블을 삭제하지 않는다. 마이그레이션 이력의 정확한 일치를 확인하는 배포 정책상 기능 코드를 되돌리는 수정 릴리스에도 014 파일을 유지해야 한다.

로컬 Node 25의 Web Storage 전역 충돌을 피하려면 전체 테스트에 `NODE_OPTIONS=--no-experimental-webstorage`를 사용한다. 운영 Docker와 CI는 Node 22를 사용한다.

## 2026-09-19 검증

- `NODE_OPTIONS=--no-experimental-webstorage npm run test:ci`: 957개 통과, 네이티브 PostgreSQL 환경을 요구하는 2개 테스트 제외. 타입 검사 및 전체 빌드 포함.
- `npm run build:oda`: 통과.
- HR 영속성 검사: 14개 SQL 마이그레이션 적용, 디스크 기반 PGlite DB 프로세스 재시작 2회 후 사진 바이트·해시·점검·멱등 결과 보존. 실제 PostgreSQL의 동시성·TLS·장애 복구 검사를 대체하지 않는다.
- 전자계약 API 영속성 회귀: DB 프로세스 재시작 3회와 양측 서명·PDF·HR 반영 통과.
