# ODA 자체 전자근로계약

2026-09-16. 모두싸인 API 연동 계획을 대체하는 ODA 내부 구현이다. 모두싸인 계정·구독·API 키가 필요하지 않다. 계약 기능의 참고 대상은 모두싸인의 공개 작성·서명·보관 흐름이며, 소스·브랜드·보안인증을 사용하지 않는다.

## 제공 범위

한 ODA 관리자 계정에서 접근 가능한 매장을 선택하고 매장별로 여러 계약 사업자를 등록한다. 사업자의 법적 이름, 사업자등록번호, 대표자, 주소, 실제 서명 담당 계정을 따로 관리한다. 서로 다른 사업자번호로 계약을 만들 수 있으며, 발송 시 해당 사업자 정보의 당시 사본을 고정한다. 사업자번호 형식 검사는 사업자 실재 여부나 대리권의 정부 확인을 의미하지 않는다.

- 인사관리 → 계약 → 자체 전자계약 / 기존 계약 기록.
- 사업자 등록·수정과 회사 서명 담당자 지정.
- 월급 전일제·시급 단시간·기간제 양식을 바탕으로 명시적인 조건 입력.
- 직원·사업자 선택, 전체 문서 미리보기, 초안 수정, 앱 내 서명 요청.
- 회사 서명권자와 직원의 개별 계정으로 서명, 서명 거절, 진행중 요청 취소.
- 원문 확인·이름 입력·자필 입력·명시적 동의·본인 계정 비밀번호 재확인.
- 모든 당사자 완료 시 계약 PDF 및 ‘ODA 계약 진행기록’ PDF를 생성하고 원본 바이트를 보관.
- 사본 교부 기록, 인사정보 반영, 직원 홈의 서명대기 안내.
- 다른 매장·직원의 계약 및 파일 접근 제한. 위치 반경은 서명 조건으로 사용하지 않는다.

서명 시 인증 수준은 **ODA 계정 로그인 + 비밀번호 재확인**이다. 통신사 명의 본인확인, 공인 시점확인, 인증서 기반 PDF 디지털 서명을 제공한다고 표시하지 않는다. PDF에는 전자서명 의사와 서명 행위의 내부 증거가 연결된다.

## 후속 처리 및 갱신 검토

- 계약 목록에서 내 서명 대기, 서명 기한 경과, 30일 내 종료 예정, 종료일 경과, 교부 확인 대기, 인사 반영 확인 항목을 선택한다. 고용주·검색 조건과 함께 적용된다. 인사 반영 확인은 적용일이 도래한 미반영 계약이며, 실제 반영은 서버에서 최신 인사조건을 다시 검사한다.
- 요청 기한 경과와 근로계약서에 기록된 종료일을 구분한다. 종료 예정 기준일은 한국 시간이며, 당일과 30일째까지 포함한다. 기록된 날짜만으로 실제 고용관계 종료를 확정하지 않는다.
- 기존 계약 상세의 ‘기존 조건으로 새 계약 작성’에서 갱신·재요청용 초안을 준비한다. 시작일·종료일을 다시 입력하고 현재 고용주와 직원을 확인한다. 기존 서명·진행기록·PDF·인사 반영 상태는 복사되지 않는다.
- 새 초안 작성은 기존 요청 취소나 기존 계약 연장을 자동 실행하지 않는다. 새 계약은 별도로 검토·요청·양측 서명을 거친다. 자동 갱신 확정이나 이전 계약 대체 관계는 기록하지 않는다.
- 직원 홈은 본인의 미서명·기한 경과·30일 내 종료 예정 계약을 안내한다. 열린 화면은 1분마다, 화면 복귀 시 다시 조회한다. 앱이 닫혀 있을 때의 푸시·문자·이메일 발송은 포함하지 않는다.

## 실제 사용 순서

1. 인사관리에서 직원을 등록하고 실제 직원의 ODA 로그인 계정을 연결한다.
2. 계약에서 사업자를 등록한다. 회사 측 서명자는 해당 매장에 접근할 수 있는 활성 계정으로 지정한다.
3. 계약 만들기에서 사업자·직원·양식을 선택하고 기간·업무·임금·근로일별 시간·휴게·휴일·연차 등의 내용을 확인한다.
4. 초안을 저장하고 전체 문서를 검토한 뒤 서명 기한을 정해 요청한다. 요청한 원문과 당사자는 수정할 수 없다.
5. 직원과 회사 담당자가 각자의 계정에서 원문을 확인하고 본인 이름·자필 서명·동의·비밀번호를 제출한다.
6. 두 당사자 완료 후 PDF 원본과 체결 시점의 진행기록을 내려받는다.
7. 실제 사본 전달을 확인하고 교부 방식·근거를 기록한다. 서버 저장·링크 표시만으로 교부 완료로 간주하지 않는다.
8. 적용일 이후 변경 전후 조건을 확인하고 인사정보에 한 번 반영한다. 기존 확정 급여는 자동으로 바꾸지 않는다.

이미 완료된 계약은 수정·삭제하지 않는다. 조건을 바꾸려면 새 계약을 작성하고 과거 문서를 보존한다. 기존 수동 계약은 기존 화면과 이력에 남으며 자체 전자서명을 거친 것으로 변환하지 않는다.

## 상태와 증거

계약 작성/서명 상태는 `draft → pending → completed`이며 진행중 거절·취소가 가능하다. 서명기한 초과는 새 서명을 차단한다. 계약기간 만료와 서명요청 기한 초과는 구분한다.

완료 원본은 별도의 `oda_contract_artifact` 행에 저장한다. 계약 원문 SHA-256과 각 PDF 파일 SHA-256은 용도가 다르다. 전자는 동의한 원문을, 후자는 내려받는 완료 파일 바이트를 대조한다. 서명 데이터(획·계정·이름·시각·재인증·동의·접속환경)는 별도 해시로 감사 이벤트 체인에 연결한다.

완료 PDF와 진행기록은 최종 서명과 같은 저장 트랜잭션으로 보관한다. 생성·보관에 실패하면 완료 상태만 따로 남지 않는다. 내려받을 때 완료 PDF를 다시 생성하지 않는다. 진행기록 PDF는 체결 시점 기록이며, 이후 교부·인사 적용 기록은 계약 상세의 추가 이력이다.

자체 해시·서버 시간·앱 및 DB의 변경 방지 규칙은 제3자 공인 인증이나 관리자까지 포함한 절대적 변조 불가능성을 뜻하지 않는다.

## 저장 구조와 권한

| 저장 단위 | 내용 |
|---|---|
| `oda_employer` | 매장별 실제 계약 사업자 및 서명 담당자 |
| `oda_contract` | 계약별 원문·조건·당사자 스냅샷·서명·진행이력·교부·적용 |
| `oda_contract_artifact` | 변경 불가 완료 PDF와 체결 진행기록 바이트 |
| `oda_hr` | 기존 직원·급여·인사 이력, 명시적 계약조건 반영 결과 |

기존 PostgreSQL aggregate 저장소에서 행을 분리해 기존 매장 전체 HR JSON에 PDF와 계약을 계속 쌓지 않는다. `012_oda_native_contracts.sql`은 매장별 사업자번호 중복, 서명요청 후 원문·당사자 변경, 완료 파일 교체·삭제를 제어한다.

권한 있는 점주·본사 관리자는 자신에게 허용된 매장의 계약을 관리한다. 서명은 계약에 지정된 당사자 계정만 가능하다. 관리자가 직원 서명을 대신할 수 없다. 재무·감사 역할에는 계약 원문 열람이 자동 부여되지 않는다. 목록은 최소 요약을 제공하고 상세·파일을 요청할 때 다시 권한을 확인한다.

비밀번호는 재인증 후 버리고 멱등 요청 해시·증빙·응답에 포함하지 않는다. 재인증 실패 횟수와 잠금 기록은 계약 실패와 함께 롤백되지 않는다. 계약 파일과 API 응답은 공용 캐시를 금지한다.

## 현재 연결 범위와 후속 항목

| 항목 | 상태 |
|---|---|
| 등록된 직원의 ODA 계정 서명 | 구현 |
| 회사 담당자와 직원의 별도 서명 | 구현 |
| 복수 사업자번호·계약별 고용주 확정 | 구현 |
| 한글 PDF 및 자필 서명·진행이력 | 구현 |
| 이메일·SMS·카카오 자동 발송 | 연결하지 않음. 외부 전송 성공으로 표시하지 않음 |
| 계정 없는 입사예정자의 외부 서명 링크 | 후속 개발. 현재는 직원 계정 연결 필요 |
| 자유 PDF 업로드·드래그 필드 편집 | 후속 개발. 현재는 구조화 근로계약 양식 |
| PASS·휴대전화 명의 인증, 인증서 PDF 서명·TSA | 별도 공급자·비용·운영 설계 필요 |
| 자동 만료 독촉·대량 발송·예약 인사반영 | 후속 개발. 현재 앱 내 요청과 명시적 적용 |
| 퇴직 후 계정 비활성화 시 셀프서비스 | 별도 포털 미구현. 퇴직 전에 사본 교부, 담당자를 통한 재교부 |
| 법정기간 경과 자동 파기 | 미실행. 문서별 기산점·보존근거·분쟁 보존 및 감사된 관리 절차 추가 필요 |

외부 전자계약 구독은 없지만 서버·보관 비용은 기존 ODA 운영비에 포함되고, 향후 외부 문자·명의 인증·신뢰된 타임스탬프 등을 연결하면 해당 비용이 발생한다. 미성년자 등 추가 요건 대상의 계약은 개별 검토와 필요한 별도 서류를 갖춘 뒤 사용한다.

## 테스트와 운영

```bash
npm run build:packages
node infra/scripts/prepare-contract-font.mjs
node --import tsx --test packages/domain/src/oda-esign.test.ts packages/domain/src/oda-hr-talent.test.ts
npm run test -w @ofd/api -- oda-esign
npm run test -w @ofd/web -- HrEsign
npm ci --prefix infra/testing/pglite --ignore-scripts
node infra/scripts/oda-esign-durable-smoke.mjs
node --import tsx infra/scripts/oda-esign-api-durable-smoke.mjs
npm run test:ci
npm run build:oda
```

내구성 스모크는 합성 데이터로 마이그레이션·고용주 유일성·원문 및 완료 파일 변경 차단·매장별 조회·디스크 DB 재시작을 검증한다. 실제 직원에게 계약을 발송하거나 실제 서명을 대행하지 않는다.

API 내구성 스모크는 실제 PostgresRepository와 12개 마이그레이션을 사용해 양측 서명·PDF 보관·중복 요청 재시도·교부·인사 반영을 실행하고, DB 프로세스를 세 번 재시작한 뒤 결과와 완료 파일의 동일성을 검증한다.

현재 ODA 전용 운영 프로필과 PostgreSQL을 재사용한다. 자체 서명에는 외부 콜백이나 모두싸인 worker가 필요하지 않다. 외부 메시지 발송을 추가하는 단계에서 별도 작업큐·발송상태·재시도를 연결한다. 기존 OFD 외부 처리 worker를 ODA에서 임의 활성화하지 않는다.
