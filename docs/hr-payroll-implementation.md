# HR 급여 구현 범위

급여 초안 생성 → 수동 항목·세액·보험 확인 → 근태 마감 확인 → 검토 → 확정 잠금 → 즉시/예약 공개를 구현했다. 재개 시 변경 사유와 기존 확정본을 보존하며 직원의 공개 화면에서는 재확정·재공개 전까지 철회한다. 상태별 변경은 서버 도메인에서 검증한다.

## 계산 계약

- 금액은 정수 원이다. 구성원 입사일부터 퇴직일까지 포함하고 귀속월 밖 구성원을 제외한다.
- `HrEmployee.history.effectiveDate`의 급여유형·금액 변경을 날짜별로 적용한다. 같은 적용일은 나중에 기록한 변경이 우선한다. 적용일별 동일 단가 구간을 묶어 계산하고 구간별 원 단위 반올림 후 합산한다.
- 월급 기본 정책: 각 구간의 월급 × 구간 재직일수 ÷ 해당월 월력일수. 윤년 2월은 29일이다.
- 선택한 전액 정책: 각 구간 월급 × 구간 재직일수 ÷ 해당월 전체 재직일수. 단가가 하나인 부분월은 월급 전액이며, 월중 단가가 바뀌면 재직기간으로 가중한다. 이 정책은 회사가 선택하는 산식이며 법정 산식이라는 주장을 하지 않는다.
- 시급: 단가 구간별 `(승인된 인정근무분 + 승인된 유급휴가분) × 시급 ÷ 60`. 무급휴가와 미달시간을 별도 공제하지 않는다. 시급 구간이 있는 행에 무급휴가 분류의 수동 공제도 허용하지 않는다.
- 근태의 자정 교차 근무는 근무 시작일에 전량 귀속된다. 근태 모듈의 마감·겹침 방지 계약을 따른다.
- 수당, 일반 공제, 월급제 무급휴가 공제는 명칭과 확정 금액을 직접 입력한다. 금액 또는 근태 원천이 바뀌면 세액·보험 검토 확인을 해제한다.
- 소득세·지방소득세·근로자 보험·회사 보험에는 자동 추정식을 넣지 않았다. `null`은 미입력, `0`은 명시적 0원이며 모든 금액을 확인해야 검토를 완료할 수 있다.
- 실지급 = 총지급 − 수동 공제 − 소득세 − 지방소득세 − 근로자 보험. 공제가 지급액을 초과하면 검토를 차단한다.

## 권한과 상태

급여 명령은 `ctx.payroll`을 요구한다. 인사관리 권한만으로 급여를 수정할 수 없다. `getHrPayrollStateForContext`는 급여관리자에게 전체를, 그 외 사용자에게 공개 시각이 도달한 본인 행만 반환한다. 직원 응답은 감사 확정본과 내부 검토 메모를 제거한다. 서버 workspace projection에도 연결했다.

검토 전에는 각 대상기간의 근태 마감과 미처리 요청 0건이 필요하다. 검토/잠금 전에 현재 인사 적용이력·근태 합계를 초안 계산 원천과 대조한다. 다르면 초안으로 재개한 뒤 최신정보 반영·재검토가 필요하다. 잠금 이후 계산 원천이 바뀌어도 보존된 급여 결과를 몰래 재계산하지 않는다. 근태 마감 해제는 연결된 급여를 먼저 재개해야 한다.

예약 공개는 조회 시 서버의 현재 시각과 비교해 제공한다. 메일·외부 알림 발송을 구현했다고 표시하지 않는다. 직원 CSV도 같은 공개·본인 필터를 적용하고 수식 형태의 문자열을 이스케이프한다.

## ODA 정산 연결점

`getHrPayrollFinalizedTotal(state, month)`는 잠금 또는 공개 상태 급여의 `총지급 + 회사 보험`을 반환한다. 근로자 원천 공제를 다시 비용으로 더하지 않는다. 이 함수 자체는 쓰기를 하지 않으며 급여 재개 시 합계에서 빠진다.

확정급여 화면의 **월 정산 인건비 미리보기**는 `GET /api/v2/oda/:storeId/hr/payroll-cost?month=YYYY-MM`으로 귀속월·총지급·회사 부담 보험·반영할 합계·기존 반영액을 조회한다. 사용자가 **월정산 인건비에 반영**을 클릭할 때만 같은 경로에 POST한다. 서버는 매장 범위와 HR·재무 접근 권한을 모두 검증하며 감사 계정은 조회만 가능하다.

POST는 HR 잠금 후 월 정산 잠금을 얻어 두 버전을 확인하고 두 원장을 한 번에 저장한다. 작성 중인 월 정산의 `hr-payroll:YYYY-MM` 인건비 행 하나를 갱신하고, 개인 성명·개인별 금액이 없는 합계 CSV 증빙을 추가한다. 기존 증빙과 다른 비용 행은 보존한다. 같은 확정본 재시도는 중복 저장하지 않으며 다른 수기 인건비나 수정된 연결 행이 있으면 중단한다. 확정·지급 완료된 월 정산은 변경하지 않는다.

급여를 재개해도 기존 월 정산 반영액을 자동으로 지우지 않는다. 급여를 다시 확정한 뒤 미리보기를 확인하고 명시적으로 재반영해야 한다. 합계가 같아도 새 확정 버전의 증빙을 보존하며, 급여 공개만으로 같은 확정본을 중복 반영하지 않는다. 성공 후 HR 화면을 다시 조회하여 다음 명령에 최신 버전을 사용한다.

## 현재 제한

- 한 귀속월에 급여 한 건만 생성한다. 추가 정산·차액 정산·여러 사업장 합산과 연간 비과세 한도 엔진은 구현하지 않았다.
- 주휴수당, 초과근무 가산율, 포괄임금, 통상임금, 보험 요율, 소득세, 퇴직금, 중도·연말정산, 30일 고정 일할, 비과세·현물 분류를 자동 계산하지 않는다. 담당자가 확인한 별도 수당·공제·세액을 입력하는 범위다.
- 휴직의 지급률·휴직기간 원장을 자동 계산하지 않는다. 휴직 구성원은 검토 메모에 지급기준 확인을 요구한다.
- 구형 구성원에 과거 생성 스냅샷이나 변경 전 스냅샷이 없으면 잃어버린 과거 단가를 복구할 수 없다. 이 경우 현재 단가를 기초로 사용한다. 신규 생성·변경은 이력을 보존한다.
- 급여 공개 명세·CSV는 구현했지만 법정 서식 PDF, 은행 이체, 국세청 신고, ERP 전송, 파일 이관은 구현하지 않았다.
- 초안 생성 당시 지급일·제목·비례 정책을 사용한다. 확정 이력이 없는 초안만 도메인의 삭제 명령으로 제거할 수 있다.

## 검증

`node --import tsx --test packages/domain/src/oda-hr-payroll.test.ts`의 12개 테스트가 입퇴사/윤년, 적용일별 월·시급, 무급휴가 비차감, 수동 세액, 비용 합계, 잠금·최신정보, 재개 보존, 본인 공개·예약·CSV, 권한·동시수정·정수·초과공제, 실패 시 부분 변경 방지를 검증한다.

연결 API의 합성 저장소 테스트는 조회 무변경, 권한·매장 범위, 두 원장 동시수정 방지, 중복 재시도, 개인정보 없는 증빙, 기존 원본 보존, 정정 후 확정 버전, 확정·지급월 차단을 검증한다. UI 테스트 4개는 자동 쓰기 없음, 명시적 반영 1회, 변경 충돌 후 새 미리보기 요구, 삭제 버튼의 중복 제출 방지, 본인 공개 범위를 검증한다. 운영 자료에 테스트 데이터를 생성하지 않았다.
